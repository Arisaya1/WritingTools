## Writing Tools v9.1 (Windows & Linux): run local models with no extra app

This release is based on upstream Writing Tools **v9** and adds two new local AI providers, plus a full control panel for running GGUF models with llama.cpp.

### ✨ New
- **LM Studio provider** connects to LM Studio's local server (default `http://localhost:1234/v1`). If you leave the model blank, it uses the first model LM Studio has loaded. (#1)
- **Built-in llama.cpp provider, "Local llama.cpp (Built-in)"**: point Writing Tools at a `llama-server` binary and a `.gguf` file, and it starts, reuses and stops the server for you. No Ollama or LM Studio needed. (#1)
  - Supports **1-bit models** such as PrismML's Bonsai (`Q1_0`) when your `llama-server` build supports them.
  - Unloads automatically after a configurable idle time (default 10 min) to free RAM/VRAM, and shuts down when you exit.
- **llama.cpp settings page: load, configure and tinker with models** (#2)
  - **Model library**: *Add Model…* or *Scan Folder…* to collect your `.gguf` files. Each entry shows its architecture, quantization, size, layer count and trained context length, read straight from the GGUF header.
  - **Load / Reload / Unload** with live status: loading time, port, llama.cpp build and an auto-unload countdown. You can cancel a load in progress, and *Show Log* streams `llama-server` output.
  - **Check llama-server** checks the binary and lists the GPUs it can use.
  - **Try It Out playground**: run a system prompt and some text against the model and watch the answer stream, with tokens/s stats. It uses the options shown on screen even before you click Save.
  - **Generation settings** (no reload needed): temperature, top-p, top-k, min-p, repeat penalty, max output tokens, seed, and a "let the model think" switch for reasoning models.
  - **Loading options**: context size, GPU layers, CPU threads, batch size, flash attention, mmap, mlock, idle unload and extra `llama-server` flags. Each section has *Reset to Defaults*.

### 🛠 Fixes
- **Linux build**: the packaged app no longer crashes on startup with `No module named 'pynput.keyboard._xorg'`. PyInstaller now bundles pynput's platform backend.
- The build script now works on Windows, Linux and macOS. It previously used the Windows-only `rmdir /s /q`.
- Closing Settings now frees a llama.cpp model you loaded there if llama.cpp isn't your active provider.

### 📦 Downloads
- **Windows**: `Writing.Tools.v9.1.Windows.zip`. Extract it (e.g. into `Documents`) and run `Writing Tools.exe`.
- **Linux (x64)**: `Writing.Tools.v9.1.Linux.zip`. Extract it, `chmod +x "Writing Tools"`, then run it. Requires X11 (the global hotkey uses pynput's X11 backend).

For llama.cpp, download a `llama-server` build from the [llama.cpp releases](https://github.com/ggml-org/llama.cpp/releases) and see the README section *"LM Studio & Built-in llama.cpp"*.

Your existing `config.json` and `options.json` keep working. The old text-based llama.cpp settings are converted automatically.
